# Daily Schedule — Lock-in Plan

My personal work/study schedule while ramping to a backend job (Django now → big tech Java later).
Two goals, one daily engine: **building + study → Django job (beachhead)**, **DSA + system design → big tech jump.**

**Guiding rules**
- Study is NOT a separate block — I learn concepts *just-in-time*, driven by the feature I'm building.
- Consistency beats heroics. 8 good hours every day for a year beats 12 that make me quit in week 2.
- Protect sleep + one rest day. They are performance tools, not luxuries.
- **Priority when hours shrink:** building first → DSA heartbeat → fundamentals → research → applications.
- Never let the streak hit zero. Momentum is the whole game.

---

## Full day (~12h target, ~10h real work + buffer)

| Block | Hours | Notes |
|---|---|---|
| Build + just-in-time study | 4 | Main engine. Project progress *and* stickiest learning. |
| Dedicated fundamentals | 1.5 | SQL, HTTP, later system design. Doesn't surface in one feature. |
| DSA | 1.5 | Focused, pattern-based, spaced repetition. Quality over volume. |
| Research / curiosity | 1.5 | Eng blogs, papers, company eng blogs. Slow-builds me into a strong engineer. |
| Applications | ~1.5 avg | **Batched into 2 sessions/week**, not daily. Some days 0, some 3. |
| Buffer / rest / overflow | ~2 | Real life, spillover, walks. Makes 12h survivable. |

---

## ~8h — normal good day
- 4h build + just-in-time study
- 1.5h fundamentals
- 1.5h DSA
- 1h research *or* applications (alternate)

## ~4h — busy day / once I'm working a job
- 2.5h build + study (integrated)
- 1h DSA
- 0.5h fundamentals *or* research
- (applications: batch on a weekend instead)

## ~2h — exhausted / minimum-to-not-break-the-chain
- 1.5h build + study
- 0.5h DSA (keep the pattern fresh — one problem)
- Everything else skipped, guilt-free.

## ~30 min — survival mode ("never zero" day)
- One DSA problem, *or* one small commit to the project.
- Just don't let the streak hit zero.

---

## How each activity actually works

**Build + just-in-time study** — Build the Django project. When a feature needs a concept (auth, serializers, permissions), read the docs *deeply right then*, because the problem makes it stick.

**Dedicated fundamentals** — The foundational stuff that doesn't come up in a single feature: SQL by hand (JOINs, GROUP BY, indexes), HTTP, and later system design. Big-tech interviews poke here.

**DSA** — Spaced repetition of *patterns*, not volume. Fully understand 2 problems, re-derive them a week later. This is the year-out big-tech gate. Language-agnostic — practicing in Python is fine.

**Applications** — Two parts:
1. *One-time setup (~4–6h once):* strong master resume + cover-letter template with swap-in slots.
2. *Per-application (~20–30 min each after setup):* find company → tweak resume keywords → fill template → submit.
Batch into ~2 sessions/week (~2h each). Don't do daily.

**Research / curiosity** — High Scalability, company engineering blogs, papers. Feels unproductive day-to-day; it's what slowly turns me into a top-tier engineer. Non-negotiable long-game.
